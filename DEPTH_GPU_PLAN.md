# Quest 3: переход с Raycast на чтение текстуры глубины шейдером

Дата среза: 2026-10-23
Связанный файл: `PROJECT_OVERVIEW.md` (проект quest-sonar, версия `v2-depth-gpu`)

> Статус: **все 4 части сделаны, скомпилированы и проверены тестом на GPU редактора** (Unity 6000.6.6f1, Meta XR Core SDK 207.0.1, MRUK 207.0.1, Direct3D12): kernel `Sample` восстанавливает точки из синтетической текстуры глубины с ошибкой ~5 мкм относительно геометрической истины, слой «нет глубины» даёт 0 точек, `flipY` действует, фильтр границ отбрасывает выбросы, `BuildQuads` корректно пишет квады в вершинный буфер меша. **v2.0 и v2.1 проверены на шлеме** (2026-10-24): запускаются, но точки из текстуры стоят не там, где препятствия (v2.0: «комната уезжает в стороны», v2.1: «случайные прямоугольники в воздухе») → **v2.2 с автокалибровкой соглашений по лучам**, см. раздел 9; v2.2 на шлеме ещё не проверена. Математика сверена по исходникам Meta, а не по памяти. Как повторить проверку: `tools/unity-check/README.md`.

## 2. Идея

`EnvironmentDepthManager` (Meta XR Core SDK) кладёт в **глобальные** шейдерные переменные:

| Переменная | Что это |
|---|---|
| `_EnvironmentDepthTexture` | карта глубины: `RenderTexture`, `Tex2DArray`, 2 слоя (глаза), depth-формат, квадратная |
| `_EnvironmentDepthReprojectionMatrices` | 2 матрицы: мировая точка → clip-пространство камеры глубины |
| `_EnvironmentDepthZBufferParams` | параметры линеаризации глубины |

Compute-шейдер читает текстуру и обратной матрицей восстанавливает мировые точки на GPU. Для отрисовки данные остаются на GPU, для карты и звука последний кадр читается на CPU через `AsyncGPUReadback` (задержка 1–3 кадра).

## 3. Факты, подтверждённые по исходникам Meta (com.meta.xr.sdk.core 207.0.1, com.meta.xr.mrutilitykit 207.0.1)

| Факт | Где в исходниках | Следствие для кода |
|---|---|---|
| `_EnvironmentDepthReprojectionMatrices[eye] = proj · view · trackingSpace.worldToLocal`, где `proj` — off-axis проекция **в стиле OpenGL** (NDC-z ∈ [−1,1], w = −z_eye), `view` — обратная поза камеры глубины в tracking space | `Scripts/EnvironmentDepth/EnvironmentDepthUtils.cs`, `EnvironmentDepthManager.OnBeforeRender` | вход — мировая точка; `invVP = matrices[slice].inverse` на CPU; в шейдере `h = invVP·(uv·2−1, raw·2−1, 1)`, `мир = h.xyz/h.w` |
| `uv = (clip.xy / clip.w + 1) / 2`, переворота Y **нет** | `Shaders/EnvironmentDepth/EnvironmentOcclusion.cginc`, `CalculateEnvironmentDepthOcclusion` | `flipY` по умолчанию выключен |
| NDC-z = `raw·2 − 1`; линейная глубина `= ZB.x / (ndcZ + ZB.y)`; `raw == 1` → «нет глубины» | там же, `SampleEnvironmentDepthLinear`; `ComputeNdcToLinearDepthParameters` | фильтр валидности в шейдере |
| MRUK восстанавливает точки на CPU ровно так: `clip = (u·2−1, v·2−1, ndcZ, 1)`, `мир = inv(VP)·clip / w` | `EnvironmentDepthRaycaster.WorldPosAtDepthTexCoord` (MRUK) | наш kernel `Sample` — та же формула на GPU |
| Собственный compute-шейдер Meta биндит глобальную `RenderTexture` обычным `SetTexture` в `Texture2DArray<float>` | `BuildingBlocks/AIBlocks/Resources/CopyDepthTextureIntoNativeArray.compute`, `DepthTextureAccess.cs` | тот же способ; запас: `bindDepthElement` → `RenderTextureSubElement.Depth` |
| Менеджер всё делает в `Application.onBeforeRender`; текстура и матрицы ставятся **независимо** от `OcclusionShadersMode`; `SoftOcclusion` (по умолчанию) добавляет препроцессинг | `EnvironmentDepthManager.cs` | читаем глобальные в `Update` (согласованная пара прошлого кадра); своему менеджеру ставим `OcclusionShadersMode.None` |
| `IsSupported` (static), `IsDepthAvailable`, `RemoveHands`, `OcclusionShadersMode` — публичные; событие `onDepthTextureUpdate` — internal; `Awake` требует ровно один менеджер | `EnvironmentDepthManager.cs` | найти существующий или добавить один |
| `EnvironmentRaycastManager` — пакет **MRUK** (namespace `Meta.XR`), провайдер по умолчанию нативный, менеджер глубины ему не нужен и не мешает | `Core/Scripts/EnvironmentRaycastManager.cs` (MRUK) | пакет MRUK должен остаться в проекте |

### Что изменилось относительно черновика Части 1 (из прошлого чата)
1. **NDC-z.** Черновик подставлял сырое значение `d` как NDC-z; по исходникам Meta нужно `d·2−1`. Это была единственная ошибка математики.
2. **Кольцевой буфер истории** сразу в `DepthSampler` (`historyFrames`), а не отдельной частью.
3. **Запасной kernel** для `Texture2D` и переключатель `bindDepthElement` вместо просто ошибки в консоль.
4. **Чередование глаз** (`alternateEyes`), сетка 112×112 (текстура квадратная).
5. Буфер обнуляется при создании (`SetData`), иначе старые слоты кольца могли бы содержать мусор.
6. Самопроверка сравнивает **расстояние между точкой и попаданием луча** (обе в мире), а не два расстояния от головы: не зависит от движения головы между кадрами.

### Почему отрисовка без собственного шейдера
Собственный вершинный шейдер + `Graphics.RenderPrimitives` на Quest требует правильных stereo-макросов (multiview) — главный «слепой» риск. Вместо этого compute-шейдер пишет готовые квады в вершинный буфер обычного меша, а рисует его `Sprites/Default`, который в проекте уже рисует частицы в стерео. Цена: 4 вершины × 20 байт на точку, ≈ 400 тыс. вершин при 8 кадрах истории — для Quest 3 приемлемо.

| Риск | Что делать |

## 8. v2.1 (2026-10-24): почему в v2.0 комната «уезжала» и что сделано

Результат первой проверки v2.0 на шлеме (Unity 2022.3.62f3): работает, но комната «как будто сходит в стороны», и в целом хуже, чем стабильная v1 на лучах.

### Разбор
1. **Формулы не виноваты.** Скачаны Meta XR Core SDK 85.0.0, 201.0.0 (последняя для Unity 2022.3) и 207.0.1: `EnvironmentDepthUtils.cs` (матрицы, линеаризация) и `EnvironmentOcclusion.cginc` побайтно одинаковы, `EnvironmentDepthManager.cs` отличается только текстами логов. Синтетический GPU-тест даёт ошибку 5 мкм.
2. **Момент чтения.** `EnvironmentDepthManager` берёт новый образ глубины и выставляет текстуру и матрицы в `Application.onBeforeRender`. v2.0 читала их в `Update`, то есть на кадр позже. На пути Oculus XR Plugin текстура — `RenderTexture` поверх образа swapchain рантайма (`XRDisplaySubsystem.GetRenderTexture(textureId)`), и рантайм перезаписывает образы по кругу новыми кадрами глубины. Шейдеры окклюзии Meta читают текстуру в том же кадре, в котором она получена, и укладываются в контракт swapchain. Чтение на кадр позже этот контракт нарушает: образ уже может содержать глубину под новую позу, а матрицы остались от старой → точки смещаются вбок ровно на движение головы за кадр. При неподвижной голове всё совпадает, при повороте комната «уезжает».
3. **Нагрузка.** 100 тыс. квадов по 2.5 см с альфа-смешиванием — примерно 10 Мпикс заливки на глаз за кадр, в 4–5 раз больше, чем 20–30 тыс. частиц в v1. На Quest 3 это может ронять кадры, а пропуски кадров в VR выглядят так же: мир плывёт вбок при движении головы.
4. **Выбросы.** Среди 12 тыс. точек в кадр всегда есть «летящие» пиксели на границах предметов (ложные близкие точки) и точки ниже пола. Минимум высоты как оценка пола «уплывает» вниз, ближайшая точка сектора в `AudioSonar` чаще ложная.

### Сделано
| Изменение | Файл |
|---|---|
| Чтение текстуры и матриц в `Application.onBeforeRender` с `[BeforeRenderOrder(1000)]` (после менеджера Meta), переключатель `sampleInUpdate` для сравнения | `DepthSampler.cs` |
| Фильтр границ: точка остаётся, если ≥ 2 из 4 соседей близки по глубине (`edgeFilter`, `edgeRelTol` 4 %, `edgeMinTol` 4 см) | `DepthSample.compute`, `DepthSampler.cs` |
| Пол по нижнему 5-му процентилю гистограммы высот за кадр вместо минимума | `ObstacleMap.cs` |
| Легче для GPU: сетка 96×96, история 6 кадров, отдельный `gpuPointSize` = 1.2 см (заливка ≈ в 7 раз меньше) | `DepthSampler.cs`, `DepthPointCloud.cs` |
| GPU-тест дополнен проверкой фильтра границ (одиночные выбросы +1 м отбрасываются, гладкая поверхность остаётся) | `tools/unity-check/CompileCheck.cs` |

### Что проверить на шлеме
1. Комната должна стоять на месте при повороте головы. Контроль причины: включить `sampleInUpdate` в Play-режиме — должно снова «уезжать»; выключить — перестать.
2. HUD: `Скан: 72/с` (если меньше — пропуски кадров: уменьшать `historyFrames`, `gridW/gridH`, `gpuPointSize`), `ошибка < 5 см`, режим `текстура`.
3. Сонар не должен пищать на пустое место рядом с краями предметов (фильтр границ); пол в HUD (`Пол: y=…`) не должен медленно уходить вниз.
4. Если всё ещё плохо — `useGpuCloud = false` (частицы) и `depthSource = Raycast` локализуют, где проблема (отрисовка или точки); стабильная v1 целиком — ветка `main`.

## 9. v2.2 (2026-10-24): точки стоят не на препятствиях — автокалибровка соглашений

Результат проверки v2.1 на шлеме: «случайные прямоугольники перед глазами в пространстве без препятствий, абсолютно неправильное вычисление точек по сравнению со стабильной версией». То есть дело не в задержке на кадр (v2.1 это убрала), а в самом восстановлении точек на устройстве.

### Что известно точно
- Формулы (`inverse(VP)·(uv·2−1, raw·2−1, 1)`, линеаризация) совпадают с исходниками Meta SDK 85/201/207 и с кодом MRUK; синтетический GPU-тест в редакторе (D3D12) даёт ошибку 5 мкм. Значит, на Quest отличается **содержимое** текстуры или способ его чтения, а не арифметика.
- Кандидаты, которые невозможно различить без устройства:
  1. **порядок глубины**: если в текстуре 1 = близко (reversed-Z, как в собственных буферах Unity на Vulkan), то формула Meta ставит близкие точки далеко и наоборот — большинство пикселей комнаты дают точки в 0.2–0.5 м от лица: крупные «прямоугольники перед глазами»;
  2. **переворот по вертикали** образа;
  3. **привязка depth-текстуры к compute-шейдеру**: у RenderTexture без цветовой части обычный `SetTexture` может дать не тот ресурс (мусор) — нужен `RenderTextureSubElement.Depth`;
  4. матрицы репроекции в другом пространстве (менее вероятно: код менеджера для SDK 85–207 одинаков).

### Сделано
| Изменение | Файл |
|---|---|
| Автокалибровка при старте: 8 вариантов (`zMode` × `flipY` × `bindDepthElement`), для каждого 2 readback по 24 сравнения точка–`Raycast`, выбор минимальной медианы, порог приёма 12 см, повтор через 10 с при неудаче; результат в HUD и логе | `DepthSampler.cs` |
| Пока `calibrated = false`: `ObstacleMap` на лучах, `DepthPointCloud` показывает частицы, а не меш | `ObstacleMap.cs`, `DepthPointCloud.cs` |
| Параметр `_ZMode` (0: raw·2−1, 1: 1−2·raw), гистограмма сырых значений `_RawHist` (`_Diag`) | `DepthSample.compute` |
| Диагностика в лог: текстура, матрица[0], `ZBufferParams`, гистограмма сырых значений с подсказкой | `DepthSampler.cs` |
| HUD: `калибровка: проверка N/8 (…)`, затем `[zX yX dX ошибка]` | `QuestRoomScanner.cs` |
| Тест: обратный порядок глубины (`_ZMode = 1` на текстуре `1−raw` даёт те же точки; `_ZMode = 0` на ней — неверные), гистограмма считает все пиксели | `tools/unity-check/CompileCheck.cs` |

### Что прислать после запуска
1. Строку HUD `Глубина: …` после калибровки (или с `не удалась`).
2. Из консоли (adb logcat / Unity Console): строки `DepthSampler: текстура глубины …`, `сырые значения глубины …`, `вариант … медианная ошибка …`, `калибровка … Все варианты: …`.
По ним станет ясно, какое соглашение у вашей версии SDK/плагина; его можно будет зафиксировать по умолчанию (`autoCalibrate = false`). Если ни один из 8 вариантов не проходит, виноваты матрицы — тогда следующий шаг: восстанавливать точки не через `_EnvironmentDepthReprojectionMatrices`, а через позу и FOV камеры глубины из `frameDescriptors` (internal в SDK; доступ через reflection).
