# Quest 3: карта препятствий, облако точек и звуковой сонар

Версия: **v2.2-depth-gpu** (2026-10-24). Предыдущие: `v2.1-depth-gpu`, `v2-depth-gpu` (2026-10-23), стабильная `v1-stable` (ветка `main`).
Статус: v2.0 и v2.1 **проверены на шлеме и работают неверно**: точки из текстуры стоят не там, где препятствия («случайные прямоугольники в воздухе»), хотя формулы совпадают с исходниками Meta и проходят синтетический тест. Значит, на устройстве соглашения текстуры глубины (порядок глубины, переворот, способ привязки depth-текстуры к compute) отличаются от ожидаемых. **v2.2 подбирает их автоматически по лучам стабильной версии** (см. «Что изменилось в v2.2») и до успешной калибровки не показывает точки из текстуры; **на шлеме ещё не проверена**. C# скомпилирован во временном проекте Unity 6000.6.6f1 с Meta XR Core SDK 207.0.1 и MRUK 207.0.1 (без ошибок); compute-шейдер проверен тестом на GPU редактора (`tools/unity-check/`): восстановление точек из синтетической текстуры глубины совпадает с геометрической истиной с точностью ~5 мкм, фильтр границ отбрасывает одиночные выбросы, запись квадов в вершинный буфер меша работает. Все новые режимы имеют откат на поведение v1 (см. «Как проверить на шлеме»).

## Цель
Помощь слепым и слабовидящим при ходьбе: Quest 3 измеряет расстояния датчиком глубины (Depth API), а приложение превращает их в пространственные звуки. Это дополнение к трости или собаке-проводнику, а не замена.

## Из чего состоит проект

| Файл (`Assets/`) | Роль |
|---|---|
| `ObstacleMap.cs` | Ядро. Берёт точки поверхностей (из текстуры глубины или лучами), строит карту препятствий (2D-сетка, вид сверху), даёт события и API |
| `DepthSampler.cs` | **Новое в v2.** Читает текстуру глубины compute-шейдером: ~9 200 мировых точек в кадр в GPU-буфер (кольцо из 6 кадров) + копия последнего кадра на CPU. Самопроверка относительно `Raycast` |
| `Resources/DepthSample.compute` | **Новое в v2.** Compute-шейдер: восстановление точек из текстуры глубины и построение квадов для облака |
| `DepthPointCloud.cs` | Отладочная визуализация: выключает passthrough, рисует облако точек. В v2 облако рисуется мешем из GPU-буфера `DepthSampler` (десятки тысяч точек); частицы остались как запасной режим |
| `AudioSonar.cs` | Превращает точки глубины в пространственные звуки + вибрацию (не менялся) |
| `QuestRoomScanner.cs` | Только HUD со статусом; в v2 добавлена строка про источник глубины |
| `SonarCommon.cs` | Общие мелочи: ожидание рига, поиск головы, материал со спрайтовым шейдером. В сцене не создаётся |

Пять основных скриптов создаются сами при старте сцены (`RuntimeInitializeOnLoadMethod`). Вешать на объекты ничего не нужно. Параметры видны в Inspector у созданных объектов во время игры. Папка `Resources` нужна, чтобы `DepthSampler` сам нашёл compute-шейдер.

## Что нужно в сцене
- `OVRCameraRig` (голова = `centerEyeAnchor`; `Camera.main` не используется, в сцене два объекта с тегом MainCamera).
- `EnvironmentRaycastManager` (класс из пакета **MRUK**, `com.meta.xr.mrutilitykit`; Depth API) и разрешение на сцену (`USE_SCENE`) на шлеме. Пакет MRUK должен остаться в проекте, хотя комнатная модель MRUK не используется.
- `EnvironmentDepthManager` (Meta XR Core SDK) — **ставить не нужно**: `DepthSampler` найдёт существующий или добавит свой (с `OcclusionShadersMode = None`, `RemoveHands = true`). В сцене должен быть не больше одного.
- Для облака точек: `OVRPassthroughLayer` (если его нет, будет только чёрный фон).
- Для лучшего звука: **Meta XR Audio SDK** и `Project Settings → Audio → Spatializer Plugin = Meta XR Audio`. Без него звук работает на обычной стереопанораме Unity.
- Манифест: PASSTHROUGH, USE_SCENE, USE_ANCHOR_API, HAND_TRACKING, supportedDevices `quest|quest3|quest3s`. Строки `BOUNDARYLESS_APP` в манифесте **нет** (она убирает системную границу Guardian; Project Setup Tool при Overwrite её удаляет).
- Unity 2023.1+ (скрипты используют `FindFirstObjectByType`, `Mesh.GetVertexBuffer`), графика Vulkan или GLES3 с compute-шейдерами (Quest 3 поддерживает).

## Как это работает

```
Quest 3 depth sensor
   │
   ├─ EnvironmentDepthManager → глобальные шейдерные переменные
   │      _EnvironmentDepthTexture (2 слоя = глаза), _EnvironmentDepthReprojectionMatrices, _EnvironmentDepthZBufferParams
   │           │
   │           ▼  DepthSample.compute, kernel Sample (каждый кадр в onBeforeRender, 96×96 точек, глаз чередуется, фильтр границ)
   │      DepthSampler.PointsBuffer  (GPU, кольцо 6 кадров ≈ 55 000 точек: xyz мир, w = расстояние)
   │           ├─ kernel BuildQuads ──► меш из квадов ──► DepthPointCloud (GPU-облако, Sprites/Default)
   │           └─ AsyncGPUReadback (последний кадр, 1-3 кадра задержки) ──► DepthSampler.Points (CPU)
   │                                                                              │
   └─ EnvironmentRaycastManager.Raycast (лучи, запасной режим и самопроверка)     │
                                                                                  ▼
                              ObstacleMap.Scan()  ── depthSource: Auto / Raycast / Texture
                                   │   ├─ OnDepthHit(Vector3)  ──► AudioSonar (сектора → звук)
                                   │   │                       └─► DepthPointCloud (счётчик близких точек; частицы, если нет GPU-облака)
                                   │   └─ карта: log-odds в клетках 0.1 м, 3 высотных слоя
                                   ▼
                            минимап, плитки на полу, HUD, API (IsOccupied, DistanceAlong, ...)
```

### 1. DepthSampler (новое в v2)
1. Ждёт риг и `EnvironmentDepthManager.IsDepthAvailable` (до 15 с). Если глубины нет (нет разрешения, не Quest 3, не поддерживается) — `ready = false`, `status` с причиной, всё остальное работает как в v1.
2. Каждый кадр **в `Application.onBeforeRender`, сразу после `EnvironmentDepthManager`** (в том же кадре, что и шейдеры окклюзии Meta) берёт глобальные переменные Meta и запускает kernel `Sample`: сетка `gridW × gridH` (96×96 = 9 216) точек с дрожанием по Хэлтону внутри ячейки, слой текстуры = глаз (чередуется, `alternateEyes`). Читать на кадр позже (в `Update`, как делала v2.0) нельзя: текстура — образ из swapchain рантайма, который к следующему кадру может быть уже перезаписан глубиной под новую позу, а матрицы останутся старыми — точки «уезжают» при движении головы. Для сравнения оставлен переключатель `sampleInUpdate`. Для каждого пикселя: `мир = inverse(VP) · (uv·2−1, raw·2−1, 1)` с делением на w — ровно то, что делает код Meta (MRUK) на CPU; фильтры: `raw ∈ (0,1)`, линейная глубина `ZB.x / (raw·2−1 + ZB.y)` в разумных пределах, расстояние от головы в `[minDistance, maxDistance]`. **Фильтр границ** (`edgeFilter`): «летящие» пиксели на границах предметов (промежуточная глубина, которой нет ни у предмета, ни у фона) отбрасываются — точка остаётся, если хотя бы 2 из 4 соседей близки к ней по глубине (допуск `max(edgeMinTol, edgeRelTol·L)`).
3. Точки пишутся в кольцевой GPU-буфер (`historyFrames` кадров, по умолчанию 6); последний кадр читается на CPU асинхронно (`Points`, `ReadbackFrame`, `validCount`).
4. **Автокалибровка** (`autoCalibrate`, при старте): перебираются 8 вариантов соглашений — `zMode` (0: NDC-z = raw·2−1, как в шейдерах Meta; 1: обратный порядок глубины), `flipY` (переворот по вертикали), `bindDepthElement` (привязка depth-части `RenderTexture` вместо обычной). Для каждого варианта 2 кадра по 24 случайные точки сравниваются с `Raycast` в ту же сторону (расстояние между точкой и попаданием луча); побеждает вариант с наименьшей медианой, он принимается, если медиана < `calibrationAccept` (12 см). Иначе `calibrated = false`, повтор через 10 с. Результат в HUD (`[z0 y0 d0 2.1 см]`) и в логе (строки `DepthSampler: вариант …`, `калибровка …`). Пока `calibrated = false`, карта остаётся на лучах, облако — частицами.
5. **Мониторинг** после калибровки: раз в 0.5 с 8 точек сверяются с `Raycast`, медиана по 16 пробам → `calibErrorMedian` (м). Лог раз в 2 с.
6. **Диагностика** (один раз при старте, в лог): описание текстуры, матрица, `ZBufferParams`, гистограмма сырых значений глубины первого кадра с подсказкой, какой порядок глубины она означает.
7. Ручной режим: `autoCalibrate = false` и выставить `zMode` / `flipY` / `bindDepthElement` самому; `eye` / `alternateEyes`; `sampleInUpdate` (чтение как в v2.0).

### 2. ObstacleMap (ядро)
1. **Источник точек** `depthSource`:
   - `Auto` (по умолчанию): точки из `DepthSampler`, если он готов, в кадре ≥ `textureMinPoints` (500) валидных точек и `calibErrorMedian` измерена и ≤ `textureMaxError` (0.1 м); иначе лучи. Переключение автоматическое, в обе стороны. Текущий режим — `activeSource`.
   - `Raycast`: всегда лучи, поведение v1.
   - `Texture`: точки, пока `DepthSampler` готов (иначе лучи).
2. **Режим Texture.** Каждый прочитанный кадр (`ReadbackFrame`) обрабатывается один раз в пределах `scanBudgetMs` (остаток — в следующем кадре). Для каждой точки: событие, пол, классификация по высоте, запись в карту — та же логика, что для луча (`ProcessHit`). Дорогие операции делаются для подвыборки: очистка клеток вдоль пути к каждой `carveEvery`-й точке (8), событие `OnDepthHit` для каждой `eventEvery`-й (4); фаза подвыборки сдвигается с каждым кадром, так что за несколько кадров покрываются все точки. Ожидаемо: ~12 000 точек/кадр, ~3 000 событий/кадр, 1–4 мс CPU.
3. **Режим Raycast.** Каждый кадр пускается столько лучей, сколько влезает в `scanBudgetMs` (5 мс), от `minRaysPerFrame` (32) до `maxRaysPerFrame` (512). Направления по последовательности Хэлтона, веер ±55° по горизонтали, от −25° (вверх) до +45° (вниз); 35% лучей (`footShare`) в зону под ноги (±35°, 10–50° вниз).
4. **Классификация точки** по высоте над полом: ниже `stepHeight` (0.15 м) — пол, проходимо; выше `headClearance` (1.9 м) — потолок, не препятствие; между — препятствие, +`hitAdd` в клетку.
5. **Очистка.** Вдоль пути от головы до точки клетки получают `missAdd`: исчезнувшие предметы стираются.
6. **Три высотных слоя** (до 0.6 м, до 1.2 м, выше), чтобы луч над низким предметом не стирал его.
7. **Пол** учится по точкам, полученным под углом вниз: за кадр строится гистограмма их высот и берётся нижний 5-й процентиль (не минимум — среди тысяч точек из текстуры всегда есть выбросы ниже пола); `floorY` плавно следует за ним; до первого определения: высота головы − `fallbackEyeHeight` 1.6 м.
8. **Забывание.** Все значения клеток плавно уходят к нулю с постоянной времени `memorySeconds` (4 с). Пустые клетки удаляются раз в 2 с.
9. **Визуализация.** Миникарта 10×10 м перед глазами (вверх = направление взгляда), плитки препятствий на полу (до 250 шт., радиус 3 м): зелёные, жёлтые (< 1.2 м), красные (< 0.6 м).
10. **API:** `Instance`, `IsOccupied(Vector3)`, `IsOccupiedCell`, `DistanceAlong(dir, max)`, `ToCell`, `CellCenter`, `ClearMap()`, `LevelColor()`, `SourceLabel`, событие `OnDepthHit`, поля `floorY`, `nearestDistance`, `nearestPoint`, `occupiedCount`, `activeSource`, `lastRays`/`lastHits` (в режиме точек: обработано/валидных), `raysPerSecond` (точек или лучей в секунду), `scanMs`, `statusCounts` (только для лучей).

### 3. DepthPointCloud (облако точек)
- **GPU-облако** (`useGpuCloud`, по умолчанию): когда `DepthSampler` готов, создаётся меш на `SlotSize × History` квадов (4 вершины по 20 байт: позиция, цвет RGBA8, uv half2; статичные индексы). Каждый кадр kernel `BuildQuads` переписывает вершины прямо в GPU-буфер меша (`Mesh.GetVertexBuffer`): квады повёрнуты к голове, размер `gpuPointSize` (по умолчанию 1.2 см: точек в десятки раз больше, чем частиц, крупные полупрозрачные квады заливают экран и ронят кадры), цвет по высоте над полом (синий внизу, красный вверху), старые кадры прозрачнее (`minAlpha` для самого старого). Материал — `Sprites/Default`, как у частиц (работает в стерео). CPU к точкам не прикасается.
- **Частицы** — запасной режим (`useGpuCloud = false` или `DepthSampler` не готов): точки по `OnDepthHit`, `pointLifetime` 2.5 с, до `maxEmitPerFrame` 120 в кадр, максимум 30 000.
- Выключает passthrough (чёрный фон). Кнопка **B или Y** переключает камеры; облако видно только при выключенных камерах.
- **Автовключение камер отключено** (`autoPassthroughBelow = 0`). Если включить, учтите: в режиме точек событий `OnDepthHit` в кадр в десятки раз больше, чем лучей, поэтому порог `closeRayCount` (3 точки ближе 0.4 м) срабатывает гораздо легче.

### 4. AudioSonar (звук)
Не менялся. Работает по событиям `OnDepthHit`, которых в режиме точек приходит ~3 000 в кадр (подвыборка `eventEvery`) вместо сотен; окно накопления `windowSec` 0.12 с сглаживает это.
1. Поле зрения делится на 5 секторов по горизонтали. В каждом секторе берётся **ближайшая** точка за окно 0.12 с (пол и потолок отбрасываются).
2. Звучат только 3 ближайших сектора (`activeSectors`), между началами звуков минимум 0.06 с.
3. **Расстояние:** частота писков от 0.8 с (далеко, 3 м) до 0.09 с (близко); громкость от 0.25 до 0.9; нота пентатонической гаммы: ближе = выше (6 ступеней).
4. **Высота:** точка ниже 0.9 м над полом = тёплый «щипок», выше = «колокольчик».
5. **Направление:** источник звука стоит в сторону точки, не дальше 1.5 м от головы. Нужен `AudioSource.spatialize` и Meta XR Audio.
6. **Опасность:** ближе 0.6 м (`ObstacleMap.dangerDistance`) почти сплошной тон + вибрация обоих контроллеров.
7. **Обрыв/ступеньки вниз:** если за окно 3+ точки попали ниже пола на 0.3 м и больше, звучит нисходящий сигнал, повтор каждые 0.7 с.
8. **Кнопка A или X** включает и выключает звук (короткий подтверждающий сигнал).
9. Звуки генерируются программой (без файлов): мягкая атака, экспоненциальное затухание, ~5% шума для лучшей локализации.

Основания выбора (исследования по сонификации для слепых): [обзор](https://www.journals.pan.pl//Content/102689/PDF/aoa-2016-0040.pdf), [IJHCS](https://opinvisindi.is/bitstream/handle/20.500.11815/702/paper_IJHCS_pre-print.pdf?sequence=3). Главное: приятные тембры вместо резких писков, ограничение числа одновременных звуков, окружающие звуки не блокировать, подбирать параметры вместе со слепыми.

## Как проверить на шлеме (v2)
1. Скопировать `Assets/` (включая `Assets/Resources/DepthSample.compute`) в Unity-проект, собрать, запустить. Первые секунды стоять неподвижно и смотреть на комнату с мебелью.
2. В HUD появится строка `Глубина: …`. Первые 1–3 с идёт калибровка (`калибровка: проверка N/8 …`), облако в это время — частицы, как в v1. Затем ожидание: `[zX yX dX ошибка]` с ошибкой **< 5 см**, `шейдер: ~8000 т.`, `~600k/с`, режим `текстура`. Облако (камеры выключены) должно быть плотным, совпадать с комнатой и оставаться на месте при повороте головы. **Главное, что нужно прислать: строку HUD после калибровки и строки консоли `DepthSampler: вариант …` / `калибровка …` / `сырые значения …`** — по ним видно, какое соглашение у вашей версии SDK, и я зафиксирую его по умолчанию.
2а. Калибровка «не удалась» (все варианты с большой ошибкой): точки из текстуры не используются, всё работает как v1; прислать те же строки консоли — это значит, что расхождение не в порядке глубины/перевороте/привязке, а в чём-то ещё (например, в матрицах), и разбираться нужно по гистограмме сырых значений.
3. **Комната «уезжает» в стороны при повороте головы** (симптом v2.0). В v2.1 чтение перенесено в `onBeforeRender`; для проверки причины включите у `DepthSampler` в Play-режиме `sampleInUpdate`: если с ним уезжает, а без него нет — причина подтверждена, выключите обратно. Если уезжает в обоих случаях — смотрите FPS в HUD (`Скан: N/с`): меньше 72 означает пропуски кадров (в VR они выглядят именно как плывущая комната) — уменьшить `historyFrames` (до старта), `gridW/gridH`, `gpuPointSize`, или `useGpuCloud = false`. Присылайте строки HUD с `sampleInUpdate` и без.
4. Ошибка большая (десятки см) или режим не переходит на `текстура`: у объекта `DepthSampler` в Inspector (в Play-режиме) по очереди: `flipY`; затем `alternateEyes = false` и `eye = 1`; затем `bindDepthElement`. Каждый раз подождать 5 с. Прислать строку HUD и консоль (строки `DepthSampler:`) с результатом.
5. Шейдер «не готов»: причина написана в HUD (`глубина недоступна`, `Depth API не поддерживается`, `не найден … DepthSample.compute`). Проверить разрешение на сцену (Space Setup / USE_SCENE) и что `.compute` лежит именно в `Assets/Resources`.
6. Облако не видно или двоится в глазах: `useGpuCloud = false` у `DepthPointCloud` — вернутся частицы.
7. Полный откат к поведению v1 без пересборки: `depthSource = Raycast` у `ObstacleMap` и `useGpuCloud = false`. Стабильная v1 целиком — ветка `main` (тег `v1-stable`).
8. Консоль: ошибки от `DepthSampler`, `DepthPointCloud`, `EnvironmentDepthManager` присылать дословно.

## Известные ограничения и риски
- **v2.1 на шлеме не проверена** (v2.0 проверена: запускается, но комната уезжала в стороны — исправлено в v2.1, см. ниже). Скомпилировано с Meta XR Core SDK 207.0.1; код глубины в SDK 85 и 201 (последняя для Unity 2022.3) идентичен; на более старых версиях тип/формат `_EnvironmentDepthTexture` может отличаться (есть запасной kernel для обычной `Texture2D` и переключатель `bindDepthElement`).
- Датчик не видит стекло, зеркала, тонкие предметы (ножки стула), плохо работает на ярком солнце. Быстро движущихся людей видит с задержкой.
- Без passthrough реальный мир не виден. Автовключение камер отключено по просьбе пользователя.
- Точки с GPU приходят с задержкой 1–3 кадра: при быстром повороте головы карта чуть отстаёт (для ходьбы незаметно).
- Определение обрыва зависит от `floorY`, которая учится по точкам и может «уплывать». Возможны ложные срабатывания.
- Тип точки (низкий/высокий тон) определяется по высоте самой ближайшей точки сектора: стена тоже считается «низкой», если ближайшая её точка низко.
- Самопроверка сравнивает точки с `Raycast` того же датчика: это проверка согласованности математики, а не абсолютной точности.
- Нагрузка: GPU-облако ≈ 220 тыс. вершин в кадр (×2 глаза) при точке 1.2 см; обход точек на CPU в пределах `scanBudgetMs`. Если FPS в HUD ниже 72: уменьшить `historyFrames` (до старта) или `gridW/gridH`, `gpuPointSize`, увеличить `carveEvery`. Пропуски кадров в VR выглядят как «плывущая» комната.
- Идентификатор пакета Meta XR Audio SDK (`com.meta.xr.sdk.audio`) назван по памяти. Если «Add package by name» не находит его, ищи в Package Manager.

## Что изменилось в v2.2 (2026-10-24, после проверки v2.1 на шлеме)
- v2.1 на шлеме: точки из текстуры стоят не на препятствиях, а «случайными прямоугольниками в воздухе». Формулы (сверенные по исходникам Meta SDK 85/201/207) и синтетический GPU-тест верны, значит на устройстве само содержимое текстуры или способ его чтения отличается: кандидаты — обратный порядок глубины (1 = близко), переворот по вертикали, обычная привязка depth-текстуры к compute-шейдеру даёт не тот ресурс.
- **Автокалибровка по лучам**: `DepthSampler` перебирает 8 комбинаций (`zMode` × `flipY` × `bindDepthElement`), сравнивая точки каждой с `Raycast` стабильной версии, и принимает лучшую, если медианная ошибка < 12 см. Результат и все медианы — в HUD и в логе. Пока калибровка не прошла, карта на лучах, облако — частицы (никаких «прямоугольников в воздухе»).
- **Диагностика** в лог один раз: описание текстуры, матрица репроекции, `ZBufferParams`, гистограмма сырых значений глубины (по ней видно порядок глубины и то, читается ли вообще текстура).
- Compute-шейдер: параметр `_ZMode`, гистограмма `_RawHist`; тест дополнен проверкой обратного порядка глубины и гистограммы.

## Что изменилось в v2.1 (2026-10-24, после первой проверки v2.0 на шлеме)
- **Причина «уезжающей» комнаты.** v2.0 читала текстуру и матрицы Meta в `Update`, то есть на кадр позже, чем их выставил `EnvironmentDepthManager` (он работает в `Application.onBeforeRender`). Текстура глубины — образ из swapchain рантайма: к следующему кадру рантайм может уже записать в него глубину под новую позу головы, а матрицы у нас остаются от старой → при движении головы точки смещаются вбок. Шейдеры окклюзии Meta читают текстуру в том же кадре, поэтому у них этого нет. Теперь `DepthSampler` тоже читает в `onBeforeRender` сразу после менеджера (`[BeforeRenderOrder(1000)]`); старое поведение оставлено переключателем `sampleInUpdate` для сравнения на шлеме.
- **Фильтр границ** в compute-шейдере: отбрасывает «летящие» пиксели на краях предметов (ложные близкие точки, от которых сонар пищал зря).
- **Пол** определяется по 5-му процентилю высот, а не по минимуму: среди тысяч точек минимум почти всегда выброс, и пол «уплывал» вниз.
- **Легче для GPU**: сетка 96×96 (было 112×112), история 6 кадров (было 8), точка облака 1.2 см (было 2.5 см) — заливка экрана примерно в 7 раз меньше, меньше риск пропусков кадров.
- Код глубины в Meta XR Core SDK 85, 201 (последняя версия для Unity 2022.3) и 207 сверен: формулы и момент выставления матриц одинаковы, так что математика v2 верна и для вашей версии SDK.

## Что изменилось в v2 (относительно v1-audio-sonar)
- Новый `DepthSampler` + `DepthSample.compute`: тысячи точек в кадр из текстуры глубины вместо сотен лучей. Математика сверена по исходникам Meta XR Core SDK 207.0.1 (`EnvironmentDepthUtils.cs`, `EnvironmentOcclusion.cginc`) и MRUK (`EnvironmentDepthRaycaster`): матрица репроекции переводит мировую точку в clip-пространство камеры глубины (проекция в стиле OpenGL), `uv = (xy/w + 1)/2` без переворота Y, NDC-z = `raw·2−1`.
- `ObstacleMap`: источник `depthSource` (Auto/Raycast/Texture), общая обработка точки `ProcessHit` для лучей и точек, обход точек с бюджетом времени и подвыборкой.
- `DepthPointCloud`: облако мешем из GPU-буфера (без собственного шейдера и без CPU), частицы как запасной режим.
- HUD: строка `Глубина: …`.
- Подробности и история решений: `DEPTH_GPU_PLAN.md`.

## Чистка кода (v1 → ветка dev, поведение не менялось)
- Повторявшийся в 4 скриптах блок «дождаться рига и найти голову» вынесен в `SonarCommon`.
- `Shader.Find("Sprites/Default")` (3 места) заменён на `SonarCommon.NewSpriteMaterial()`: при отсутствии шейдера в билде есть запасной вариант и понятное предупреждение вместо падения.
- `ObstacleMap`: цвет по дистанции (`LevelColor()`), признак «клетка пустая» (`IsCellSeen`) и расстояние по горизонтали вынесены в одно место; магические числа стали константами; `Instance` обнуляется, материалы и текстура уничтожаются в `OnDestroy`; устаревший комментарий про `raysPerFrame` исправлен.
- `AudioSonar`: убран дублирующий `dangerDistance` (берётся из `ObstacleMap.dangerDistance`, значение то же, 0.6 м); сортировка секторов и создание клипов вынесены в методы; упрощён подтверждающий сигнал кнопки.
- `QuestRoomScanner`: цвет HUD через `map.LevelColor()`.

## Идеи на потом
1. Распознавание ступенек (подъём): повторяющиеся уступы 15–20 см перед пользователем.
2. Режим «пинг» по кнопке: проход слева направо за 1–2 с.
3. Кластеризация точек в объекты с рамками.
4. Голосовые подсказки для редких событий («дверь справа, 2 м»).
5. Свободный проход: тихий тон в сторону самого дальнего просвета.
6. Карта и звук целиком на GPU (сейчас точки для карты читаются на CPU).
7. Распознавание объектов: Passthrough Camera API + ML.
8. Тесты со слепыми и слабовидящими пользователями и подбор параметров звука.

## Как вернуться к предыдущим версиям
Репозиторий на GitHub: **https://github.com/Anikor/quest-sonar** (ветка по умолчанию `main` = v1, работа в `dev`). На ПК с Unity проще клонировать его, чем переносить zip: `git clone -b dev https://github.com/Anikor/quest-sonar.git`.

Репозиторий git содержит:
- тег `v1-audio-sonar` и ветку `stable/v1-audio-sonar` (только v1, не менять);
- тег `v2-depth-gpu` (эта версия);
- ветку `dev` (для дальнейшей работы).

```bash
git checkout stable/v1-audio-sonar        # посмотреть v1 целиком
git checkout dev                          # вернуться к работе
git checkout v1-audio-sonar -- Assets/    # откатить файлы в текущей ветке к v1 (потом удалить DepthSampler.cs и Resources/)
```
Без git: папки `snapshots/v1-audio-sonar/` (четыре файла v1) и `snapshots/v2-depth-gpu/` (файлы `Assets/` версии v2.0; актуальная v2.1 — в `Assets/` и на GitHub, тег `v2.1-depth-gpu`).

Проверка кода без шлема (компиляция + GPU-тест шейдера во временном Unity-проекте): `tools/unity-check/README.md`.
