# Quest 3: карта препятствий, облако точек и звуковой сонар для слепых

Версия: **v4.0-stable** (2026-10-30), ветка `main`. Это рабочая версия с ПК со шлемом: проверена на Quest 3.
Предыдущая звуковая навигация v3.1 (зоны, «путь свободен», стук двери) в `main` не вошла: она лежит в ветке
`archive/v3.1-audio-zones` (на шлеме не проверялась). Дальнейшая работа идёт в ветках `sound` (звук) и `vision` (двери, таблички, текст).

## Цель
Помощь слепым и слабовидящим при ходьбе: Quest 3 измеряет расстояния датчиком глубины (Depth API), приложение строит карту
препятствий и превращает её в пространственные звуки: где препятствие, как близко, какой высоты; отдельно - ориентиры (двери,
окна, текст табличек). Это дополнение к трости или собаке-проводнику, а не замена.

## Из чего состоит репозиторий

| Путь | Роль |
|---|---|

| `Assets/AudioSonar.cs` | **Звук v4.** Три независимые полосы (центр / лево / право), дальность по скорости ходьбы, три класса предмета по высоте (тембр), «опасно» и «стоп» с вибрацией, обрыв, ориентиры из `SonarLandmarks`, исключение руки и трости, внешние боковые датчики, режимы эксперимента |
| `Assets/SonarLandmarks.cs` | **Реестр ориентиров** (двери, окна, текст): `Report / Remove / All / MakeId`, `SpeakHandler` для голоса. Источник из модели комнаты MRUK включается символом `USE_MRUK` |

| `Assets/QuestRoomScanner.cs` | HUD: препятствие, пол, статистика лучей, состояние шейдера глубины и источник позы |

Скрипты создаются сами при старте сцены (`RuntimeInitializeOnLoadMethod`), вешать ничего не нужно. Параметры видны
в Inspector у созданных объектов во время игры.

## Что нужно в сцене
- `OVRCameraRig` (голова = `centerEyeAnchor`).
- `EnvironmentRaycastManager` (пакет MR Utility Kit, Depth API) и разрешение на сцену на шлеме.
- `OVRPassthroughLayer` для переключения камер (B / Y).
- **Meta XR Audio SDK** и `Project Settings → Audio → Spatializer Plugin = Meta XR Audio` для HRTF. Без него - стереопанорама Unity.
- Манифест (в репозитории): PASSTHROUGH, USE_SCENE, USE_ANCHOR_API, HAND_TRACKING, BOUNDARYLESS_APP, `quest|quest3|quest3s`.

## Как это работает

```
Quest 3 depth sensor
        │  EnvironmentRaycastManager.Raycast (синхронный луч)
        ▼
 ObstacleMap.Scan()  ── каждый кадр, N лучей (по бюджету времени 5 мс, 32..512)
        │   ├─ OnDepthHit(Vector3) ──► AudioSonar.OnHit: точка → полоса (центр / лево / право) → слои по 0.1 м
        │   │                      └─► DepthPointCloud: частицы (если GPU-облако не активно)
        │   └─ карта: log-odds в клетках 0.1 м, 3 высотных слоя, пол по лучам вниз
        ▼
 AudioSonar.Publish (каждые 0.12 с): ближайший слой с >= 2 точками, класс по высоте, центр масс → писки
 SonarLandmarks.All ──► AudioSonar.UpdateLandmarks: мелодии двери / окна / текста + SpeakHandler(текст)
```

### 1. ObstacleMap (как в v3.0)
1. **Лучи.** Каждый кадр столько лучей, сколько влезает в `scanBudgetMs` (5 мс), от 32 до 512; направления по Хэлтону;
   веер ±55° по горизонтали, −25° (вверх) … +45° (вниз); 35% лучей в зону под ноги.
2. **Классификация** по высоте над полом: ниже 0.15 м пол, выше 1.9 м потолок, между - препятствие (+`hitAdd`).
3. **Очистка** вдоль луча (`missAdd`), **три слоя** по высоте (до 0.6 / до 1.2 / выше), **пол** учится по лучам вниз,
   **забывание** с постоянной времени 4 с.
4. **Визуализация:** миникарта 10×10 м, плитки на полу (зелёные / жёлтые < 1.2 м / красные < 0.6 м).

### 2. AudioSonar v4 (звук)
Три независимые полосы, у каждой свой источник звука и свой ритм:
- **Центр**: коридор перед вами (`pathHalfWidth` 0.4 м в обе стороны) до текущей дальности. Главный сигнал.
- **Лево / право**: вне коридора, ближе `sideRange` 1 м (и чуть позади курса, `sideBehind` 0.25 м). Тише, с той стороны.
- На пути и по бокам чисто = тишина. Ничего не звучит непрерывно, всё короткие импульсы.

| Сигнал | Что значит | Параметры |
|---|---|---|
| «тук» (140 Гц) / «щипок» (220 Гц) / «колокольчик» (320 Гц) | предмет НИЗКИЙ (< 0.4 м) / СРЕДНИЙ / ВЫСОКИЙ (> 1.15 м). Ближе = чаще, громче и выше нота (пентатоника) | `minInterval` 0.15 … `maxInterval` 0.55 с, `noteBands` 6 |
| частые низкие импульсы + вибрация | опасная близость: ближе `dangerNow` (дальность × 0.35, 0.3…0.9 м), ритм ускоряется к контакту | `dangerMinInterval` 0.10 … 0.24 с |
| частый высокий писк 1400 Гц + сильная вибрация | «стоп»: вплотную, ближе `contactNow` (дальность × 0.2, 0.2…0.4 м). Единственный высокий звук | `contactInterval` 0.10 с |
| нисходящий свист | обрыв / ступеньки вниз: 3+ точки ниже пола на 0.3 м | `dropRepeat` 0.7 с |
| «динь-дон» / две короткие вверх / три щелчка | ориентир из `SonarLandmarks`: дверь / окно / текст (в секторе ±50°, до 3 м, не чаще раза в 8 с на ориентир) | `landmarkCues`, `speakLandmarkNames` |
| короткий низкий / высокий | подтверждение: звук выключен / включён (A / X) | |

- **Дальность по скорости**: стоя и до 1 км/ч - 0.5 м, при 3 км/ч - 2 м, дальше растёт до `maxRange` 3 м; меняется не быстрее 2 м/с.
- **Направление**: источник ставится по курсу (без наклона головы), угол преувеличен в `azimuthGain` 2 раза, мёртвая зона ±6°,
  положение = центр масс ближайших слоёв (+0.2 м), сглаживание 0.6; дальше 1.5 м источник не отодвигается (громкость задаётся явно).
- **Рука и трость**: точки в сфере 0.22 м вокруг кисти/контроллера и вдоль отрезка трости (1.4 м, радиус 0.1 м, правая рука) выбрасываются.
- **Внешние боковые датчики**: `SetExternalSide(leftMeters, rightMeters)` для ультразвука/ToF на очках (необязательно).
- **Режимы эксперимента** `AudioSonar.Mode`: Off / Mono (один источник по центру, без боковых полос) / Spatial / SpatialVoice.
- Кнопка **A / X** включает и выключает звук (если `toggleWithButtons`; `ExperimentController` это отключает и занимает кнопки).

### 3. SonarLandmarks (ориентиры)
`AudioSonar` сам ничего не распознаёт по картинке; он озвучивает то, что сообщено в реестр:
```csharp
int id = SonarLandmarks.MakeId(LandmarkKind.Door, worldPos);   // стабильный id по типу и клетке 0.5 м
SonarLandmarks.Report(id, LandmarkKind.Door, worldPos);          // живёт ttl = 2 с без обновления
SonarLandmarks.Report(id, LandmarkKind.Text, worldPos, "ВЫХОД"); // текст будет произнесён через SpeakHandler
SonarLandmarks.SpeakHandler = MyTts.Speak;                        // подключение голоса
```
Источники: модель комнаты MRUK (`MrukLandmarkSource`, символ `USE_MRUK`), детекторы по камере (ветка `vision`).

### 4. ExperimentController
Левый стик (нажать) = следующее условие (A → B → C → D), правый стик = столкновение, левый курок = ложная тревога,
правый курок = конец попытки (строка в `trials.csv` в `Application.persistentDataPath`). Номер участника: `participant.txt` там же.
Условие D: каждые 2 с голосом «впереди / слева / справа» + «близко / метр / два метра» (Android TTS, язык `voiceLanguage` = ru, запасной en).

### 5. DepthPointCloud и DepthSampler
- Частицы по `OnDepthHit`, цвет = высота над полом; кнопка **B / Y** переключает камеры.
- `DepthSampler` читает `_EnvironmentDepthTexture` compute-шейдером (сетка 128×96, 12 кадров истории) и сравнивает точки с `Raycast`.
  На Quest 3 (Horizon OS, 2026-10-24) работает `eye=0, flipY=false, zMode=4` (ошибка ~2.7 см); `autoSearch` выключен, включайте, если ошибка снова большая.
  Поза камеры глубины: K запоминается по первой матрице Meta, дальше берётся текущая поза глаза (`poseFromHead`), иначе матрицы «застывают».
- GPU-облако включается после первой успешной самопроверки (ошибка ≤ 5 см) и остаётся включённым. На карту и звук эти точки не влияют.

## Управление

| Кнопка | Действие |
|---|---|
| A / X | Включить или выключить звук сонара (если не запущен `ExperimentController`) |
| B / Y | Включить или выключить passthrough (облако точек) |
| Левый хват | `DepthSampler`: поза камеры глубины из глаза / из матрицы |
| Левый стик / правый стик / курки | `ExperimentController`: условие / столкновение / ложная тревога / конец попытки |

## Известные ограничения и риски
- Датчик не видит стекло, зеркала, тонкие предметы (ножки стула), плохо работает на ярком солнце.
- Звук считается относительно взгляда (датчик на голове): смотреть надо туда, куда идёшь.
- Обрыв зависит от `floorY`, которая учится по лучам и может «уплывать».
- Ориентиры появляются только если кто-то их сообщает: без `USE_MRUK` и без ветки `vision` реестр пуст.
