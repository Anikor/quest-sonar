# quest-sonar: звуковой сонар и «зрение» для слепых на Meta Quest 3

Приложение для Quest 3, которое превращает шлем в навигационный прибор для незрячего человека:

- **датчик глубины** строит карту препятствий вокруг и озвучивает её короткими пространственными звуками
  (где препятствие, какой высоты, как близко, где обрыв);
- **камера passthrough** читает таблички и номера кабинетов вслух и находит двери, в том числе закрытые;
- **режимы работы** и **панель порогов** позволяют подстроить прибор под человека и под задачу прямо в шлеме,
  без экрана и без компьютера.

Это дополнение к трости или собаке-проводнику, а не замена. Всё работает офлайн, на самом шлеме.

Состояние на 2026-10-31: ветка `main` = ветка `vision`, собирается и запускается на Quest 3. Звуковой сонар проверен
на шлеме в нескольких сессиях; чтение табличек проверено; распознавание дверей по картинке (своя нейросеть) установлено
на шлем и ждёт первого прогона; режимы и панель порогов проверены компиляцией и тестом, на шлеме ещё нет.

## Что умеет

**Сонар (ветка `sound`, файл `AudioSonar.cs`)**
- Карта препятствий с клеткой 0.1 м из лучей датчика глубины, три слоя по высоте, пол учится сам.
- Три звуковые полосы: коридор перед собой, слева, справа. Чисто = тишина.
- Высота предмета слышна по тембру (низкий «тук», средний «щипок», высокий «колокольчик»), расстояние по ритму и громкости.
- «Опасно» и «стоп» при сближении, свист при обрыве или ступеньках вниз.
- Дальность подстраивается под скорость ходьбы: стоя 0.5 м, при быстром шаге до 3 м.
- Рука и трость из карты исключаются; есть вход для внешних боковых датчиков.
- Экспериментальный контур: условия A-D, запись попыток в `trials.csv`.

**Зрение (ветка `vision`, папка `Assets/Vision`)**
- Чтение табличек: Tesseract OCR на кадре камеры, румынский + английский (русский подключается), два прохода
  (весь кадр и увеличенные области), обе полярности, отдельный проход для крупного номера кабинета на тёмной полосе
  («3-212»). Текст подтверждается двумя сканами, многострочная табличка читается построчно с паузами, только целые слова.
- Чтение вслух через общий голосовой модуль `SpeechOutput`: фоновый поток, одна фраза в очереди, без наложений,
  повтор одной и той же таблички не чаще раза в 15 с, дальность чтения 2 м.
- Двери из трёх источников: нейросеть по картинке (своя модель, обученная на фотографиях помещений, видит закрытые двери),
  геометрический проём на карте глубины (открытая дверь), табличка с номером кабинета (дверь рядом с ней).
- Каждая дверь: звонок из её направления, голос «дверь впереди / слева / справа», жёлтая метка на минимапе.
- Журнал `vision-log` (события, кадры по запросу, карты ASCII) для разбора после прогона на ПК.
- Вибрация контроллеров выключена.

**Режимы и настройка (папка `Assets/Modes`)**
- Семь режимов: навигация, только опасность, текст, ориентиры, узкий проход, тишина, эксперимент.
- Панель порогов в пространстве: все пороги сонара с ограничениями (контакт < опасность < дальность), сохранение
  в PlayerPrefs, сброс, запись значений в `thresholds.csv` рядом с `trials.csv`, чтобы замеры были воспроизводимы.
- Кнопки эксперимента работают только в режиме «Эксперимент», случайное нажатие больше не глушит сонар.

## Как это устроено

```
                 Quest 3                                    Unity (этот репозиторий)
 ┌────────────────────────────────┐
 │ датчик глубины                 │──EnvironmentRaycastManager──► ObstacleMap  (карта 0.1 м, 3 слоя, пол)
 │ (Meta Depth API)               │                                   │   │
 └────────────────────────────────┘                                   │   └──► DoorFinder ◄── NavZones.FindPassages
                                                                      │           (проём 0.45-1.6 м, стены по краям,
                                                                      ▼            глубина за ним ≥ 1 м, 2 скана)
                                                                AudioSonar  (полосы, тембры, «опасно», «стоп», обрыв)
                                                                      ▲
                                                      SonarLandmarks.All (реестр дверей / окон / текста)
                                                                      ▲
 ┌────────────────────────────────┐                                   │
 │ камера passthrough             │──PassthroughCameraFeed──┬──► SignReader ──► TesseractRecognizer (фоновый поток)
 │ (Passthrough Camera API, MRUK) │   серый кадр + поза      │          │  слова → таблички → подтверждение → точка в мире
 └────────────────────────────────┘                          │          └──► SpeechOutput (TTS) и Report(Text)
                                                             │
                                                             └──► DoorVision ──► Unity Sentis, YOLOv8n «doors-indoor»
                                                                        рамка → луч → глубина → DoorFinder.ReportVisionDoor

 OperatingModeController ── задаёт публичные поля AudioSonar / SignReader / DoorFinder под режим, включает
 TuningPanel            ── ExperimentController только в «Эксперименте», пишет thresholds.csv
```

Подробно по модулям: сонар и карта в `PROJECT_OVERVIEW.md`, зрение в `VISION.md`, режимы в `docs/MODES_AND_TUNING.md`.

### Поток дверей
1. **Картинка.** Раз в 1.5 с кадр 416×416 проходит через YOLOv8n на GPU шлема (около 0.1 с). Рамка класса «door»
   с уверенностью ≥ 0.35 и высотой ≥ 18% кадра даёт луч через её центр; луч упирается в карту глубины и даёт точку.
   Две детекции в радиусе 1.2 м подтверждают дверь, она держится 6 с после последней.
2. **Карта.** Раз в 0.5 с ищутся сквозные проёмы между высокими (> 1.2 м) объектами на расстоянии от 0.8 до 5 м:
   ширина 0.45-1.6 м, хотя бы с одной стороны стена (а не край шкафа), за проёмом не меньше метра свободно.
   Косые проёмы учитываются. Нужны два скана подряд.
3. **Табличка.** Если в прочитанном тексте есть номер кабинета, рядом регистрируется дверь на 30 с.
4. Все источники сливаются в `DoorFinder` (радиус слияния 1.2 м). Дверь в секторе ±70° и ближе 4 м получает звонок
   из своего направления и голос, не чаще раза в несколько секунд. Открывание и закрывание двери видно по карте:
   закрытая дверь пропадает с карты, но остаётся по картинке.

### Поток текста
Кадр 1280×960 раз в 2.5 с (чаще, пока текст в кадре; пропускается, когда голова движется быстрее 30°/с).
Проход 1: разреженный текст на всём кадре, обычная и инвертированная полярности. Проход 2: найденные области
вырезаются, увеличиваются и читаются как блок. Проход 3: полоса над текстом табличек, где обычно крупный номер,
читается как одна строка цифр несколько раз с разными окнами, ответ по голосованию. Слова чистятся (минимум букв,
правдоподобие, повтор на двух полярностях), группируются в таблички по геометрии строк; табличка, увиденная дважды
(или один раз с уверенностью ≥ 85%), произносится. Если в ней есть номер, впереди добавляется слово «дверь».

## Сигналы и голос

| Звук | Значение |
|---|---|
| «тук» 140 Гц / «щипок» 220 Гц / «колокольчик» 320 Гц | предмет низкий (< 0.4 м) / средний / высокий (> 1.15 м); ближе = чаще, громче и выше |
| частые низкие импульсы | опасная близость (дальность × 0.35, 0.3-0.9 м), ритм ускоряется к контакту |
| частый высокий писк 1400 Гц | «стоп»: вплотную (дальность × 0.2, 0.2-0.4 м); единственный высокий непрерывный звук |
| нисходящий свист | обрыв или ступеньки вниз: точки ниже пола на 0.3 м |
| двойной звонок 660/880 Гц из направления | дверь (все три источника) |
| «динь-дон» / две ноты вверх / три щелчка | ориентир из реестра: дверь / окно / текст (мелодии сонара) |
| короткий тон при смене режима | подтверждение переключения режима (голосом не дублируется) |

Голос говорит только результаты: текст табличек (построчно), «дверь впереди / слева / справа», ближайшая дверь по запросу
в режиме «Ориентиры», короткие служебные фразы по правому хвату («текста не видно», «камера не готова»). Язык голоса
берётся из того, что принял движок: румынский, потом русский, потом английский.

## Управление и режимы

| Кнопка | Действие |
|---|---|
| Левый стик вправо / влево, держать 0.3 с | следующий / предыдущий режим (короткий тон) |
| Левый стик нажать | назвать текущий режим (вне режима «Эксперимент») |
| Правый курок | действие режима: «Текст» прочитать то, что перед тобой; «Ориентиры» ближайшая дверь, сторона и расстояние |
| Правый хват | прочитать вслух весь текст в кадре (в любом режиме) |
| X | открыть / закрыть панель порогов |
| Правый стик ↑ ↓ / ← → / нажать | в панели: выбрать параметр / изменить / значение по умолчанию; дважды вправо на последней строке = сбросить всё |
| B / Y | passthrough с облаком точек глубины (отладка) |
| Левый хват | `DepthSampler`: поза камеры глубины из глаза / из матрицы (отладка) |
| Стики и курки в режиме «Эксперимент» | `ExperimentController`: условие A-D, столкновение, ложная тревога, конец попытки |

Режимы по кругу:

| Режим | Что звучит | Для чего |
|---|---|---|
| **Навигация** (по умолчанию) | весь сонар, двери, таблички | обычная ходьба |
| **Только опасность** | «опасно», «стоп», обрыв; дальних писков нет | знакомое место, шумная улица |
| **Текст** | сонар как «только опасность», курок читает текст | найти кабинет, прочитать объявление |
| **Ориентиры** | двери и окна, курок называет ближайшую дверь | поиск выхода, ориентация в коридоре |
| **Узкий проход** | коридор уже, дальность меньше, боковые полосы громче | дверной проём, проход между столами |
| **Тишина** | звук выключен, «стоп» можно оставить | разговор, отдых; включается с голосовым предупреждением |
| **Эксперимент** | как настроил `ExperimentController`, пороги зафиксированы | замеры с участниками |

Смена режима никогда не оставляет человека без «опасно» и «стоп», кроме явной «Тишины». При выходе из режима
прежние значения полей сонара восстанавливаются.

Панель порогов правит `dangerDistance`, `contactDistance`, `maxRange` (или `rangeSlow` / `rangeFast` при автодальности),
`sideRange`, `pathHalfWidth`, `dropDepth`, `landmarkRange`, `masterVolume`, `haptics` и переключатель «ручные пороги»
(фиксированные значения вместо масштабирования от дальности). Ограничения: контакт < опасность < дальность с зазором
0.1 м, боковая дальность не больше основной; нарушение прижимается и показывается на панели.

## Сборка и установка

```bash
git clone https://github.com/Anikor/quest-sonar.git
cd quest-sonar
```

**В редакторе.** Открыть папку в Unity 2022.3.62f3, установить пакеты из `Packages/manifest.json`
(на ПК без Asset Store подставить `tools/build/manifest-this-pc.json`), File → Build Settings → Android → Build.
Если `ProjectSettings/` нет, первый запуск выставит значения по умолчанию, а `BuildQuest.cs` поправит всё нужное при сборке.

**Из командной строки** (так собиралось всё, что стоит на шлеме):

```bat
"C:\Program Files\Unity\Hub\Editor\2022.3.62f3\Editor\Unity.exe" -batchmode -quit ^
  -projectPath "C:\путь\к\quest-sonar" -executeMethod BuildQuest.Build -logFile build.log
```

Результат: `Builds/quest-sonar.apk` (IL2CPP, ARM64, Vulkan, Linear, minSdk 32, targetSdk 34, пакет `com.anikor.questsonar`).
`BuildQuest.cs` сам регистрирует XR-настройки из `Assets/XR`, спатиализатор Meta XR Audio и нужные шейдеры.

**На шлем** (режим разработчика и USB-отладка включены, запрос на шлеме подтверждён):

```bat
adb install -r -g Builds\quest-sonar.apk
adb shell am start -n com.anikor.questsonar/com.unity3d.player.UnityPlayerActivity
```

`adb` лежит в `…\Editor\Data\PlaybackEngines\AndroidPlayer\SDK\platform-tools\`. Флаг `-g` сразу выдаёт разрешения;
при первом запуске шлем всё равно спросит доступ к камере, нужно разрешить. Разметка комнаты (Space Setup) не нужна.

## Голос на шлеме: eSpeak NG

Системный синтезатор Quest сторонним приложениям недоступен (блокирует вызов на секунды и не отдаёт языков), поэтому
приложение ищет **eSpeak NG** и пользуется им. Один раз на каждом шлеме:

```bat
adb install espeak-ng.apk                                        :: APK с F-Droid, пакет com.reecedunn.espeak
adb shell am start -n com.reecedunn.espeak/.DownloadVoiceData    :: распаковать голоса (первый запуск)
adb shell settings put secure tts_default_synth com.reecedunn.espeak
```

Порядок языков в `SpeechOutput`: румынский, русский, английский; берётся первый, который движок принял. Если eSpeak
не найден, приложение пробует движок по умолчанию и системный, текст при этом может молчать (в журнале будет `tts_init`).

## Журналы и разбор прогонов

Шлем не обязан быть подключён во время теста: всё пишется на него, забирается потом.

| Файл на шлеме (`/sdcard/Android/data/com.anikor.questsonar/files/`) | Содержимое |
|---|---|

## Нейросеть дверей: как переобучить

Модель `doors-indoor.onnx` = YOLOv8n, дообученная на наборе DoorDetect (MiguelARD, 1210 фотографий помещений,
классы `door`, `handle`, `cabinet door`, `refrigerator door`), 60 эпох, 640 px, экспорт в ONNX 416 px, opset 15.

| Показатель (121 проверочных фото, все классы) | Значение |
|---|---|
| точность / полнота | 0.70 / 0.61 |
| mAP50 | 0.66 |
| размер / вычисления | 12 МБ, 3.7 GFLOPs |
| время на Quest 3 (GPU, 416 px) | около 0.1 с |

Общие модели (COCO, Open Images) закрытые двери в наших коридорах не видели ни разу, поэтому обучена своя.

```bash
cd tools/door-model
git clone https://github.com/MiguelARD/DoorDetect-Dataset data     # набор в ./data
pip install ultralytics torch --index-url https://download.pytorch.org/whl/cu128
python train_doors.py          # ~5 минут на RTX 4070; кладёт модель в Assets/Vision/Resources/doors-indoor.onnx
python export_trained.py       # только экспорт уже обученных весов
```

`DoorVision.cs` берёт первую найденную модель из списка `doors-indoor`, `doors-oiv7`; номер класса двери читается
из файла `<модель>-door-class.txt` рядом. Другой набор данных или другая модель подключаются без правки кода.

## Ветки, версии и правила совместной работы

| Ветка / тег | Что | Состояние |
|---|---|---|
| `main` | всё вместе: сонар v4 + зрение + режимы; на 2026-10-31 совпадает с `vision` | собирается, стоит на шлеме |
| `vision` | зрение: таблички, двери, голос, режимы, панель порогов | рабочая ветка зрения |
| `sound` | звук: `AudioSonar.cs`, `ExperimentController.cs`, тембры, ритмы, голосовые подсказки | рабочая ветка коллеги, создана от `v4.0-stable` |
| тег `v4.0-stable` | звук v4 с ПК со шлемом (2026-10-30), без зрения | проверен на шлеме |
| `archive/v3.1-audio-zones`, тег `v3.1-audio-zones` | звуковые зоны v3.1, `NavZones.cs` | на шлеме не проверялась |
| тег `v3.0-stable` | карта и звук v1, `DepthSampler` с автоподбором | проверен на шлеме |
| `dev`, теги `v2.*-depth-gpu` | карта по текстуре глубины | остановлено |

Граница между ветками: реестр `SonarLandmarks` и голос `SpeechOutput`.

- `vision` **не меняет** `AudioSonar.cs` и `ExperimentController.cs`: режимы и панель работают через их публичные поля,
  предложения правок к ним лежат в `docs/MODES_AND_TUNING.md` как «было / стало».
- `sound` **не меняет** `Assets/Vision/` и `Assets/Modes/`.
- В общих файлах ветка `vision` добавила только `ObstacleMap.QueryCell`, `ObstacleMap.mapMarks` и `SignReader.ReadNow()`.
- Публичные поля и методы не переименовывать, в сцену ничего не класть, хранилище только PlayerPrefs и CSV.
- Слияние в `main` после проверки на шлеме; версии, проверенные на шлеме, помечаются тегами `vX.Y-stable`.

Вернуться к любой версии: `git checkout v4.0-stable` (или другой тег), собрать тем же `BuildQuest.Build`.

## Известные ограничения

- **Датчик глубины** не видит стекло, зеркала, тонкие предметы (ножки стула) и слабеет на ярком солнце. Звук считается
  от взгляда: смотреть нужно туда, куда идёшь.
- **Закрытая дверь** на карте глубины неотличима от стены, её находит только нейросеть по картинке. Модель обучена на
  чужих фотографиях; её работа на дверях конкретного здания пока не подтверждена прогоном, порог уверенности и минимальный
  размер рамки могут потребовать подстройки по журналу.
- **Двери по карте** иногда находятся между мебелью (проход между шкафами тоже сквозной проём); правило «стена по краю»
  убирает большинство, но не все ложные срабатывания.
- **Tesseract** читает крупный печатный текст с 1-2 м; мелкий, под углом и при плохом свете нет. Шрифты с засечками и
  логотипы дают мусор, который отсеивается, но не всегда.
- **Голос eSpeak NG** разборчивый, но механический; системный синтезатор Quest использовать нельзя.
- OCR занимает одно ядро на 0.5-3 с каждые 2.5 с; нейросеть дверей 0.1 с каждые 1.5 с. Вместе с сонаром кадровая частота
  держится, но при добавлении новых детекторов интервалы придётся увеличивать.
- Режимы и панель порогов на шлеме ещё не прогонялись (чек-лист в `docs/MODES_AND_TUNING.md`, раздел 9).
